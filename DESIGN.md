## Overview

A reading platform first: a wiki (encyclopaedic reference), a bibliography (structured catalogue), and an e-reader (long-form literary text). The same tokens drive all three contexts. The system is built on CUBE CSS + Every Layout primitives, with Tailwind used solely as a design-token compiler. Sources of truth are the JSON files in [`src/_data/designTokens/`](src/_data/designTokens/) — this file's frontmatter is regenerated from them by [`src/_config/setup/build-design-md.js`](src/_config/setup/build-design-md.js); the body below is hand-written.

## Colors

The palette has two layers: a four-stop **base** ramp that defines the surfaces of both themes, and four **period accents** drawn from the four periods of Tolstoy's life. Sources: [`colorsBase.json`](src/_data/designTokens/colorsBase.json) (raw values) and [`semanticColors.json`](src/_data/designTokens/semanticColors.json) (theme-bound surface roles). Period research: [`docs/design/period-colours-research.md`](../docs/design/period-colours-research.md), refined in [`docs/design/period-colours-preview.html`](../docs/design/period-colours-preview.html).

### Base ramp — surfaces

Light theme surfaces are warm parchment-grey; dark theme surfaces are slate charcoal. The same four-stop ramp drives both.

| Slot | Hex | Role |
|---|---|---|
| `base-darkest` | `#272b30` | Dark theme page bg |
| `base-dark` | `#30353c` | Dark theme card surface (lifted from bg) |
| `base-light` | `#dcd9d0` | Light theme page bg |
| `base-lightest` | `#e8e4db` | Light theme card surface (lifted from bg) |

### Period accents

| Period | Slot | Light theme | Dark theme tint |
|---|---|---|---|
| I — Youth & Formation | `green` | `#4A7C59` | `#7DBF92` |
| II — Soldier & Sinner | `red` | `#B83232` | `#E06868` |
| III — The Great Works | `amber` (full ramp) | `#a48200` (`amber-500`) | `#DDB840` (`amber-tint`) |
| IV — The Prophet | `blue` | `#2362A0` | `#5DA0DC` |

Amber is generated as a full 100–900 ramp (vibrant); the other three are single-value slots with `subdued` (–20% chroma) and `tint` (lighter, dark-theme override) siblings. **Colour is always paired with shape, label, or position — never the sole carrier of meaning.** This holds across the knowledge graph, timeline, and UI, as accessibility and as defensive design.

### Semantic surface tokens

Components consume these — never the raw ramp values.

**Light theme** (`:root`, `:root[data-theme='light']`)

| Token | Resolves to | Purpose |
|---|---|---|
| `--color-bg` | `base-light` | Page background |
| `--color-bg-accent` | `base-lightest` | Card / elevated surface |
| `--color-bg-accent-2` | `gray-300` | Dividers, `<hr>` |
| `--color-text` | `base-darkest` | Body copy |
| `--color-headline` | `base-darkest` | Headings |
| `--color-text-accent` | `gray-700` | Captions, metadata |
| `--color-accent-{amber,red,blue,green}` | period values | Interactive accents (one per period) |
| `--color-link-underline` | `amber-600` | Link underline |

**Dark theme** (`prefers-color-scheme: dark` / `:root[data-theme='dark']`)

| Token | Resolves to | Purpose |
|---|---|---|
| `--color-bg` | `base-darkest` | Page background |
| `--color-bg-accent` | `base-dark` | Card / elevated surface |
| `--color-bg-accent-2` | `gray-600` | Dividers |
| `--color-text` | `gray-250` | Body copy |
| `--color-headline` / `--color-text-accent` | `gray-200` | Headings, captions |
| `--color-accent-{amber,red,blue,green}` | `*-tint` values | Interactive accents (lighter than light theme) |
| `--color-link-text` | `amber-tint` | Link colour |

Both `prefers-color-scheme: dark` and `:root[data-theme='dark']` resolve to identical tokens. The `--color-accent-*` semantic layer abstracts over light/dark — components reference `--color-accent-amber` and the theme block handles the swap to the lighter tint.

### Contrast — to be verified

Pairs to audit against WCAG AA (`text` 4.5:1, `UI` 3:1):

## Typography

### Typeface selection

The project uses the Adobe Source family exclusively — a deliberate choice that provides cohesion across display, body, and code, while the family's classical proportions suit scholarly text.

| Role | Typeface | Weights | Fallback |
|---|---|---|---|
| Display (headings) | Source Serif 4 | 700 | Georgia Bold, serif |
| Body | Source Sans 3 (variable) | 400, 700 | Arial, sans-serif |
| Monospace | Source Code Pro | 400 | Fira Code, Menlo, monospace |

**E-reader.** Source Serif 4 is an excellent reading typeface — designed for long-form text with optical sizing support. The e-reader should default to Source Serif and offer Source Sans 3 (400) as an alternative for readers who prefer a sans face. Enable `font-optical-sizing: auto`.

### Type scale

Generated via Utopia fluid type (320px → 1350px viewport). Base: 19px → 28px (`step-0`). Modular ratio: 1.2 (minor third) → 1.25 (major third).

| Token | Min → Max (px) | Typical use |
|---|---|---|
| `step-min-2` | 13 → 16 | Micro labels, footnote numbers |
| `step-min-1` | 16 → 22 | Captions, metadata |
| `step-0` | 19 → 28 | **Body text (base)** |
| `step-1` | 23 → 35 | Lead paragraphs |
| `step-2` | 27 → 44 | H3, blockquote |
| `step-3` | 33 → 55 | (unused currently) |
| `step-4` | 40 → 68 | H2 |
| `step-5` | 47 → 86 | H1 section title |
| `step-6` | 56 → 107 | H1 hero / display |

Current heading map: `h1` → `step-6`, `h2` → `step-4`, `h3` → `step-2`. Wiki article titles likely want a `.wiki-title` modifier sized to `step-4` — `step-6` is too large for non-hero pages.

The e-reader should use `step-0` as default body and expose a user control (±1 step) persisted in `localStorage`.

### Line height

| Token | Value | Use |
|---|---|---|
| `flat` | 1.0 | Single-line labels, tight elements |
| `extrafine` | 1.1 | H1 hero display |
| `fine` | 1.2 | H2, H3 |
| `standard` | 1.4 | Body text, paragraphs |
| `fibonacci` | 1.618 | Long-form reading (e-reader body) |

`fibonacci` is defined but not currently applied to prose. Use it for `.reader .prose` paragraphs in the e-reader. `standard` is correct for wiki and UI prose.

### Letter spacing

| Token | Value | Use |
|---|---|---|
| `--tracking` | `-0.04ch` | Default body |
| `--tracking-s` | `-0.075ch` | Tight headings |
| `--tracking-wide` | `+0.09ch` | Small caps, metadata labels |

Negative tracking on Source Sans 3 is intentional — the typeface's generous default spacing benefits from slight tightening at large sizes.

### Line length

`.prose` enforces `max-inline-size: 60ch` on paragraphs and list items (canonical 55–75ch range). The prose wrapper itself widens to `64rem` (≈ 80ch) to accommodate headings and figures that run wider than body. The e-reader should enforce a tighter 65–70ch with comfortable lateral margin and centred text column on wide screens.

### Text rendering

Currently applied: `font-size-adjust: from-font` on `body` (cross-font x-height normalisation).

Recommended additions:

- `text-rendering: optimizeLegibility` on body (ligatures + kerning)
- `hanging-punctuation: first last` on prose paragraphs (optical alignment for opening quotes)
- `font-variant-numeric: oldstyle-nums` for inline dates and numbers in long-form text
- `hyphens: auto` on `.prose` body paragraphs (currently only at narrow viewports)

## Layout

### Spacing scale

Generated via Utopia fluid spacing, same viewport range as type. All values are `clamp()` expressions resolved at runtime — see frontmatter `spacing.*` for the resolved max-px values.

Default gutter: `--gutter: var(--space-m-l)` (14 → 31px). Used by wrapper, sidebar, and cluster compositions.

### Every Layout primitives

Currently implemented (in `src/assets/css/global/compositions/`):

| Primitive | Purpose |
|---|---|
| Flow / Stack | Vertical rhythm between elements |
| Cluster | Inline wrapping groups (tags, nav) |
| Grid | Auto-fill responsive grid |
| Repel | Two items pushed to opposite ends |
| Sidebar | Two-column with one fixed-width column |
| Wrapper | Max-width centred container (85rem) |

Likely additions for the e-reader:

- **Cover** — chapter openers (centred content within a min-height)
- **Center** — the reading column itself (intrinsically centred with max-inline-size)
- **Frame** — image aspect-ratio containers (portraits, cover art)

## Elevation & Depth

Surfaces lift via the `--color-bg-accent` / `--color-bg-accent-2` token pair, not box-shadow:

- `--color-bg` — page background.
- `--color-bg-accent` — first elevation: cards, code blocks. Lighter than bg in light theme, lighter than bg in dark theme (always toward perceptual brightness).
- `--color-bg-accent-2` — second elevation: dividers, `<hr>`. Visually further differentiated from bg.

No box-shadow elevation system is defined and none is intended; depth is colour-based only, in keeping with the literary aesthetic.

## Shapes

Border radius scale (frontmatter `rounded.*`):

| Token | Value | Use |
|---|---|---|
| `none` | `0px` | Default — flat edges throughout |
| `sm` | from `borderRadius.json` | Code blocks, small surfaces |
| `md` | from `borderRadius.json` | Cards, larger surfaces |

Default is `none` — flat edges. Round only when there is a clear functional reason.

## Components

Component-level token wiring lives in the frontmatter `components.*` block — each entry references background/text/border tokens by name, not raw hex. Render them via the corresponding CSS in `src/assets/css/global/blocks/` (one file per block: `button.css`, `prose.css`, `site-footer.css`, `main-nav.css`, etc.) and `src/assets/css/local/` for genuinely page-specific styles.

The frontmatter currently defines 13 component entries (`body`, `body-dark`, `heading-1/2/3`, `link`, `link-hover`, `blockquote`, `code-block`, `hr`, `figcaption`, `focus-ring`, `selection`). Adding a new component means: (a) defining its CSS in `global/blocks/`, (b) adding its token wiring to the `COMPONENTS` map in `build-design-md.js`, (c) regenerating with `npm run penpot:tokens`.

## Do's and Don'ts

**Do:**

- **Reach for Every Layout primitives before writing custom layout CSS.** Media queries are a last resort.
- **Treat legibility as the constraint that overrides decoration.** Typeface, line length, contrast, spacing — all subordinate to comfortable reading.
- **Use the `--color-accent-*` semantic layer**, not raw ramp tokens (`--color-amber-500`, etc.), in component CSS. The semantic layer is what swaps between light and dark.
- **Pair every period colour with shape, label, or position.** Colour is never the sole signal.
- **Edit JSON tokens, not the frontmatter YAML.** Run `npm run penpot:tokens` to regenerate.

**Don't:**

- **Don't create page-specific stylesheets** (e.g. `local/homepage.css`) without flagging the need in [`docs/splash-site-plan.md`](../docs/splash-site-plan.md) and justifying it. Reuse `global/blocks/` first.
- **Don't add box-shadows for elevation.** Use the `bg-accent` / `bg-accent-2` token pair.
- **Don't assume orange.** The Amber slot was renamed from Orange in Task 1b (2026-05-09). All `--color-orange-*` and `--color-accent-orange` references are gone — refer to `--color-amber-*` or `--color-accent-amber`.
- **Don't ship red/green-distinguished UI without colour-blindness review.** The primary maintainer has deuteranopia; pair every red/green distinction with shape, label, or position.

### Open

These remain unsettled and should be revisited:

1. **Sepia theme tokens** — design and add to `colors.json` for the e-reader.
2. **Dark mode contrast audit** — verify `--color-accent-amber` (`#DDB840`) and other period tints meet WCAG AA against `--color-bg` dark (`#272b30`). UI 3:1, body text 4.5:1.
3. **Wiki article heading hierarchy** — `step-6` is too large for non-hero pages. Add `.wiki-title` modifier at `step-4`.
4. **Line-height for e-reader prose** — change `.reader .prose` flow to `fibonacci` (1.618) instead of `standard` (1.4).
5. **Font loading** — ensure `font-display: swap`, Latin + Latin Extended subset, variable axis for Source Sans 3 (`wght` 300–900).
6. **Icon system** — none currently defined. A small inline SVG sprite (not icon-font, not external lib) for wiki UI and reader controls.
